# v0.2 Intelligent Planning Loop Specification

## Objective

Transform Codex Pro Planning Bridge from a one-time planning assistant into a continuous planning and validation system.

The system should ensure that ChatGPT Pro plans remain aligned with the real repository state during implementation.

---

# Architecture

```
ChatGPT Pro
     |
     v
PLAN.md
     |
     v
Plan Validator
     |
     v
Codex Implementation
     |
     v
Repository Scanner
     |
     v
Plan Diff
     |
     v
Updated Planning Context
```

---

# Feature 1: Plan Validator

## Purpose

Check whether a generated plan matches repository reality.

## Input

```
.codex/pro-plan/

PLAN.md
repo-tree.txt
project-context.md
```

## Output

```
VALIDATION_REPORT.md
```

## Validation Rules

### File validation

Check:

- referenced paths exist
- file ownership is correct
- modules are available

### Symbol validation

Check:

- classes
- functions
- interfaces
- exported APIs

### Dependency validation

Check:

- package dependencies
- framework versions
- unavailable libraries

---

# Feature 2: Repository Fact Checker

## Purpose

Identify assumptions made by planning models.

Example:

Plan:

```
Add UserService.refreshToken()
```

Repository:

```
UserService does not exist
```

Result:

```
ASSUMPTION_ERROR
```

---

# Feature 3: Plan Diff Engine

## Purpose

Measure implementation drift.

Input:

```
PLAN.md
current repository state
```

Output:

```
PLAN_DIFF.md
```

Categories:

- completed
- missing
- changed
- blocked

---

# Feature 4: Project Memory

## Purpose

Maintain long-term project knowledge.

Directory:

```
.codex/project-memory/
```

Files:

## architecture.md

System architecture overview.

## decisions.md

Architecture Decision Records.

## constraints.md

Technical limitations.

## known-issues.md

Persistent problems.

# Acceptance Criteria

v0.2 is complete when:

1. A generated PLAN.md can be validated automatically.
2. Invalid assumptions are reported.
3. Implementation drift can be detected.
4. Project decisions can persist across sessions.
5. Documentation explains the complete planning loop.
