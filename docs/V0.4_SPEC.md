# Codex Pro Planning Bridge v0.4 Specification

Status: **Planned**  
Target version: `0.4.0-alpha.1`  
Base version: `v0.3.3-beta.1`

## 1. Version goal

v0.4 changes the product from a CLI-first bridge into a client-first plugin that can be installed and discovered in ChatGPT and Codex.

The intended user experience is:

```text
ChatGPT Pro
  -> read an explicitly registered repository through read-only MCP tools
  -> produce and validate an implementation-ready plan
  -> emit a structured Plan Capsule
  -> user approves the planning direction
  -> hand the conversation or Plan Capsule to Codex
  -> Codex imports, revalidates, and locally approves the exact PLAN.md hash
  -> Codex implements and tests the change
  -> the plugin reviews drift and updates project memory
```

The existing `cpb` CLI remains the local runtime and troubleshooting interface. It is no longer the default user-facing entry point.

## 2. Product principles

1. **ChatGPT Pro is the planning surface.** High-effort architectural reasoning happens in a normal ChatGPT Pro conversation, not through the OpenAI API.
2. **Codex is the implementation surface.** Source-code writes, test execution, and Git operations occur in Codex or the local development environment.
3. **The repository is the source of truth.** Chat content never overrides repository facts, local validation, plan hashes, or approval records.
4. **Human approval remains mandatory.** Approval expressed in ChatGPT is planning intent only. Codex must still create a local `PLAN.md`, validate it, and obtain an explicit local approval bound to its SHA-256 hash.
5. **The ChatGPT Pro MCP path is read-only in v0.4.** No ChatGPT-side tool may write source files, planning files, workflow state, project memory, or Git state.
6. **No OpenAI API integration.** The plugin must not require `OPENAI_API_KEY`, call the Responses API, or create a second model bill.
7. **No automated webpage submission.** The plugin must not drive the ChatGPT website through Playwright, DOM scripting, Computer Use, or output scraping.
8. **Local CLI compatibility is retained.** Existing `cpb` commands remain supported for advanced use, CI, recovery, and debugging.

## 3. Current platform assumptions

The implementation must be feature-gated and tested against current OpenAI surface availability.

- Plugins may package Skills, an MCP server connection, or both.
- `.codex-plugin/plugin.json` is the package manifest.
- `skills/` contains repeatable model workflows.
- `.app.json` maps a registered ChatGPT MCP connection.
- `.mcp.json` may bundle a local MCP server for Codex.
- ChatGPT and Codex share the universal plugin directory, although individual capabilities may be surface-specific.
- ChatGPT Pro can develop Apps SDK plugins and connect read/fetch MCP tools in developer mode.
- Full MCP write/modify actions are not a v0.4 Pro dependency.
- ChatGPT cannot connect directly to a local MCP server. Development must use a remote endpoint or Secure MCP Tunnel.

Authoritative references:

- https://developers.openai.com/plugins/concepts/plugins
- https://developers.openai.com/plugins/build/skills
- https://developers.openai.com/plugins/build/mcp-server
- https://developers.openai.com/plugins/build/plugins
- https://help.openai.com/en/articles/12584461-developer-mode-and-full-mcp-connectors-in-chatgpt

Because platform availability can change, the test plan must record the exact ChatGPT client, plan, developer-mode state, and rollout behavior used for acceptance.

## 4. Target surfaces

### 4.1 ChatGPT Pro planning surface

Primary capabilities:

- discover the plugin and the planning Skill;
- list registered repositories;
- read bounded repository status, context, symbols, constraints, and project memory;
- draft an architecture plan;
- call the local validator through a read-only MCP tool using plan text as input;
- revise the plan after validation;
- emit a Plan Capsule suitable for handoff to Codex.

Forbidden capabilities:

- create or edit local files;
- approve a local plan hash;
- modify workflow state;
- run arbitrary shell commands;
- accept arbitrary absolute filesystem paths;
- execute repository code.

### 4.2 Codex implementation surface

Primary capabilities:

- discover the implementation and review Skills from the same plugin;
- receive a Plan Capsule or imported ChatGPT conversation;
- write the exact `PLAN.md` locally;
- run `cpb validate` and display findings;
- request explicit approval from the user;
- run `cpb approve` only after that approval;
- execute the approved plan with normal Codex filesystem and shell capabilities;
- run tests and build checks;
- run drift review and update project memory.

### 4.3 Advanced CLI surface

The existing CLI remains available for:

- repository registration;
- diagnostics;
- manual planning workflows;
- snapshot, recovery, integrity, event, and rollback operations;
- testing the MCP service layer without ChatGPT.

## 5. Plugin composition

The v0.4 plugin contains:

```text
codex-pro-planning-bridge/
├── .codex-plugin/plugin.json
├── .app.json                         # generated after ChatGPT MCP registration
├── .mcp.json                         # bundled local MCP server for Codex
├── skills/
│   ├── plan-project-with-pro/
│   ├── implement-approved-plan/
│   └── review-implementation/
├── mcp_server/
│   ├── server.py
│   ├── service.py
│   ├── schemas.py
│   ├── tools.py
│   └── transports/
│       ├── streamable_http.py
│       └── stdio.py
├── src/codex_pro_planning_bridge/    # existing runtime
└── tests/
```

The Skills are the workflow layer. The MCP server is the live repository data layer. The existing Python package is the deterministic runtime shared by both.

## 6. Required Skills

v0.4 ships three focused Skills:

1. `plan-project-with-pro`
   - intended primarily for ChatGPT Pro;
   - calls read-only repository tools;
   - produces a validated Plan Capsule;
   - never claims that conversational approval is a local executable approval.

2. `implement-approved-plan`
   - intended for Codex;
   - imports the Plan Capsule;
   - revalidates against current repository state;
   - asks for explicit local approval;
   - implements only the approved scope.

3. `review-implementation`
   - intended primarily for Codex, optionally usable in ChatGPT for read-only review;
   - compares implementation with plan and baseline;
   - reports drift, tests, risks, and project-memory updates.

Detailed requirements are in `docs/v0.4/SKILLS_SPEC.md`.

## 7. Required MCP tools

The first release exposes exactly five read-only tools:

- `list_repositories`
- `get_repository_status`
- `prepare_planning_context`
- `validate_plan`
- `review_implementation`

All tools:

- accept `repository_id`, never an arbitrary local path;
- are marked `readOnlyHint: true`, `destructiveHint: false`, and `openWorldHint: false`;
- return structured output plus concise model-readable text;
- enforce repository authorization server-side;
- use bounded output and deterministic schemas;
- do not mutate local artifacts.

Detailed contracts are in `docs/v0.4/MCP_TOOL_CONTRACTS.md`.

## 8. Repository registration

A new allowlist-backed repository registry is required.

CLI:

```bash
cpb repo add <repository-id> <path>
cpb repo list
cpb repo show <repository-id>
cpb repo remove <repository-id>
cpb repo doctor <repository-id>
```

The MCP server receives only `repository_id` and resolves it through this registry. Canonical paths, symlink behavior, file boundaries, and registry storage are defined in `docs/v0.4/REPOSITORY_REGISTRY_AND_SECURITY.md`.

## 9. Plan handoff

ChatGPT Pro cannot be assumed to write local files in v0.4. The planning Skill therefore emits a structured Plan Capsule containing:

- schema version;
- plan ID;
- repository ID;
- repository HEAD observed during planning;
- context digest;
- goal;
- generated timestamp;
- validation summary;
- complete plan Markdown.

Codex imports this capsule, writes `PLAN.md`, recomputes local hashes, revalidates, and obtains local approval. Conversational approval is not accepted as a substitute for `APPROVAL.json`.

The protocol is defined in `docs/v0.4/HANDOFF_PROTOCOL.md`.

## 10. Deployment topology

Development topology:

```text
ChatGPT Pro
    |
    | Streamable HTTP MCP
    v
Secure MCP Tunnel
    |
    v
Local read-only MCP server
    |
    v
Repository registry -> existing cpb runtime
```

Codex topology:

```text
Codex
    |
    | bundled stdio MCP and/or local shell
    v
existing cpb runtime
    |
    v
registered local repository
```

Production/public plugin topology may use a stable hosted MCP endpoint, but hosting is not required for the first local alpha. Packaging and connection registration are defined in `docs/v0.4/PACKAGING_DEPLOYMENT_AND_TESTING.md`.

## 11. Scope

### In scope

- client-first plugin architecture;
- three focused Skills;
- read-only Repository MCP service;
- dual MCP transports over one service layer;
- repository allowlist and management CLI;
- Plan Capsule handoff;
- plugin manifest and registered connection wiring;
- local marketplace testing;
- Secure MCP Tunnel development path;
- ChatGPT Pro and Codex end-to-end tests;
- version synchronization across package and manifest.

### Out of scope

- OpenAI API model calls;
- ChatGPT-side filesystem writes;
- ChatGPT-side source modification;
- automatic web submission or scraping;
- arbitrary shell execution through MCP;
- arbitrary path access;
- multi-agent planning;
- custom interactive UI in the first alpha;
- public marketplace submission before local dogfooding;
- replacing the existing workflow reliability layer.

## 12. Acceptance criteria

v0.4 alpha is complete when all of the following are true:

1. The same plugin package is discoverable on supported ChatGPT and Codex surfaces.
2. ChatGPT Pro can list an allowlisted repository and retrieve bounded planning context without an API key.
3. ChatGPT Pro can draft and locally validate a plan using only read-only MCP tools.
4. The planning Skill emits a schema-valid Plan Capsule.
5. Codex can import that capsule, write `PLAN.md`, revalidate it, and require explicit local approval.
6. No implementation begins when the repository HEAD or context digest has materially changed without revalidation.
7. Codex can implement, test, and review the plan using the existing reliability controls.
8. The MCP server rejects unknown repository IDs, path traversal, symlink escapes, malformed schemas, oversized requests, and write attempts.
9. MCP Inspector and direct unit/integration tests pass.
10. End-to-end tests cover ChatGPT planning, Codex handoff, local approval, implementation, and drift review.
11. No OpenAI API key or OpenAI API request is introduced.
12. Documentation explains installation, developer-mode registration, tunnel setup, and fallback behavior when a surface is unavailable.
