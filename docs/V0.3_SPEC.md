# Codex Pro Planning Bridge v0.3 Specification

## Version Goal

v0.3 upgrades the project from a planning assistant into a continuous planning loop system.

The goal:

```
Task
 |
 v
Context Collection
 |
 v
ChatGPT Pro Planning
 |
 v
Plan Validation
 |
 v
Codex Implementation
 |
 v
Drift Detection
 |
 v
Memory Update
 |
 v
Next Iteration
```

v0.3 is not an autonomous coding system. It is a structured collaboration layer:

```
ChatGPT Pro = Architect
Codex = Engineer
Repository = Source of Truth
```

---

# 1. Planning Workflow State Machine

## Purpose

Convert independent tools into a recoverable workflow engine.

New component:

```
src/codex_pro_planning_bridge/workflow.py
```

States:

```
NEW_TASK

CONTEXT_READY

PLAN_READY

VALIDATING

IMPLEMENTING

REVIEWING

COMPLETED

FAILED
```

Each state transition must be explicit and recorded.

Example:

```
NEW_TASK
   |
   v
CONTEXT_READY
   |
   v
PLAN_READY
   |
   v
VALIDATING
```

---

# 2. Workflow State Persistence

## Purpose

Allow interrupted workflows to resume.

New component:

```
src/codex_pro_planning_bridge/state.py
```

Storage:

```
.codex/workflow/

state.json
history.json
```

Example:

```json
{
  "state": "VALIDATING",
  "plan": ".codex/pro-plan/PLAN.md",
  "started": "2026-08-20T00:00:00Z"
}
```

Requirements:

- versioned schema
- migration support
- human-readable format
- Git friendly

---

# 3. Planning Loop Engine

New component:

```
src/codex_pro_planning_bridge/loop.py
```

Responsibilities:

- coordinate workflow states
- load ProjectContext
- load Plan
- trigger Validator
- trigger Fact Checker
- trigger Diff Engine
- update Memory
- persist workflow state

The loop must not modify source code automatically.

---

# 4. Structured Data Models

Existing foundation:

```
src/codex_pro_planning_bridge/models.py
```

Primary models:

- ProjectContext
- Plan
- ValidationReport
- FactFinding
- MemoryEntry
- DriftReport
- WorkflowState

All workflow components should communicate through typed models.

Avoid unstructured dictionaries between core modules.

# 6. Repository Intelligence Layer

## Purpose

Improve validation beyond file-level matching.

New component:

```
src/codex_pro_planning_bridge/intelligence/

symbol_index.py
```

Generate local repository knowledge:

```
File
 |
 +-- Class
      |
      +-- Function
           |
           +-- Dependency
```

Initial support:

- Python AST
- JavaScript / TypeScript parser
- Rust symbol extraction

No external AI API required.

# 7. Enhanced Plan Validation

Validator should check:

## File existence

Example:

```
PLAN:
modify src/auth.py

Repository:
missing
```

## Symbol existence

Example:

```
PLAN:
change UserService.refresh()

Result:
not found

Possible matches:
AuthService.refresh_token()
```

## Dependency consistency

Detect:

- missing packages
- invalid imports
- removed interfaces

# 11. Non Goals

v0.3 does not include:

- OpenAI API calls
- automatic ChatGPT webpage scraping
- browser automation
- autonomous source code modification
- bypassing Codex approval

---

# 12. Acceptance Criteria

v0.3 is complete when:

1. Workflow can resume after interruption.
2. Planning state is persisted locally.
3. PLAN.md can be validated against repository facts.
4. Repository symbols can be indexed locally.
5. Drift reports include file and symbol level changes.
6. Complete planning loop can run on a real repository.
