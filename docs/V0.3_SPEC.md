# Codex Pro Planning Bridge v0.3 Specification

## Version Goal

v0.3 upgrades the project from a planning assistant into a continuous planning loop system.

The goal:

```
Task
 |
 v
Context Collection
 |
 v
ChatGPT Pro Planning
 |
 v
Plan Validation
 |
 v
Codex Implementation
 |
 v
Drift Detection
 |
 v
Memory Update
 |
 v
Next Iteration
```

v0.3 is not an autonomous coding system. It is a structured collaboration layer:

```
ChatGPT Pro = Architect
Codex = Engineer
Repository = Source of Truth
```

## 1. Planning Workflow State Machine

New component:

```
src/codex_pro_planning_bridge/workflow.py
```

States:

```
NEW_TASK
CONTEXT_READY
PLAN_READY
VALIDATING
IMPLEMENTING
REVIEWING
COMPLETED
FAILED
```

Each state transition must be explicit and recorded.

## 2. Workflow State Persistence

New component:

```
src/codex_pro_planning_bridge/state.py
```

Storage:

```
.codex/workflow/
  state.json
  history.json
```

Requirements:

- versioned schema
- migration support
- human-readable format
- Git friendly

## 3. Planning Loop Engine

New component:

```
src/codex_pro_planning_bridge/loop.py
```

Responsibilities:

- coordinate workflow states
- load ProjectContext
- load Plan
- trigger Validator
- trigger Fact Checker
- trigger Diff Engine
- update Memory
- persist workflow state

The loop must not modify source code automatically.

## 4. Structured Data Models

Primary models:

- ProjectContext
- Plan
- ValidationReport
- FactFinding
- MemoryEntry
- DriftReport
- WorkflowState

All workflow components should communicate through typed models and avoid
unstructured dictionaries between core modules.

## 5. Project Memory Evolution

The existing Markdown and ADR memory remains stable. Add:

```
.codex/project-memory/migrations/
```

This directory stores memory schema upgrades and backward-compatibility notes.
ADR remains the preferred architecture decision format.

## 6. Repository Intelligence Layer

New component:

```
src/codex_pro_planning_bridge/intelligence/symbol_index.py
```

The local index represents:

```
File
 |
 +-- Class
      |
      +-- Function
           |
           +-- Dependency
```

Initial support:

- Python AST
- JavaScript / TypeScript source parsing
- Rust symbol extraction

No external AI API is required.

## 7. Enhanced Plan Validation

The validator checks file existence, symbol existence, dependency consistency,
missing packages, invalid imports, and removed interfaces. Possible local
symbol matches should be shown when a plan references an unavailable symbol.

## 8. Enhanced Plan Diff

Plan Diff consumes `PLAN.md`, `context.json`, Git changes, and the symbol index.
It writes `PLAN_DIFF.md` and reports completed tasks, missing tasks, changed
architecture, renamed files, symbol movement, unexpected changes, and
implementation drift.

## 9. CLI Evolution

Unified commands:

```bash
cpb init
cpb collect
cpb prompt
cpb validate
cpb diff
cpb memory list
cpb loop
```

`cpb loop` advances the local workflow as far as repository evidence and
explicit human/Codex approval allow. It can be resumed after interruption.

## 10. Testing Requirements

Tests cover:

- unit behavior
- workflow recovery
- Python, JavaScript/TypeScript, and Rust symbol extraction
- an integration run on a sample repository

## 11. Non Goals

v0.3 does not include:

- OpenAI API calls
- automatic ChatGPT webpage scraping
- browser automation
- autonomous source code modification
- bypassing Codex approval

## 12. Acceptance Criteria

v0.3 is complete when:

1. Workflow can resume after interruption.
2. Planning state is persisted locally.
3. `PLAN.md` can be validated against repository facts.
4. Repository symbols can be indexed locally.
5. Drift reports include file and symbol level changes.
6. A complete planning loop can run on a real repository.
