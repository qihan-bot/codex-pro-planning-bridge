# Codex Pro Planning Bridge v0.3.2 Specification

## Version Goal

v0.3.2 is the hardening release after the v0.3.1 Planning Safety Layer. It
improves auditability and recovery while keeping the repository local and the
ChatGPT Pro/Codex boundary explicit.

Design principles remain:

```
ChatGPT Pro = Architect
Codex = Engineer
Human = Final Approver
Repository = Source of Truth
```

## 1. Approval Hash Binding

`APPROVAL.json` must bind an approval to both the canonical repository-relative
`PLAN.md` path and the exact SHA-256 digest of its contents. An approval is
ineffective when either binding is missing, malformed, mismatched, or when the
plan no longer exists. Existing v0.3.1 records that contain both bindings
remain readable.

## 2. Event Query CLI

Add a read-only command for `.codex/workflow/events.jsonl`:

```bash
cpb events --repo .
cpb events --repo . --event WORKFLOW_ROLLBACK --format json
cpb events --repo . --actor user --limit 20
```

Queries may filter by event, actor, source state, target state, ISO-8601 time
bounds, and result limit. Output includes a one-based event index that refers
to the valid append-only event stream. Querying must not initialize or rewrite
workflow state.

## 3. Workflow Rollback

Add an explicit rollback command:

```bash
cpb rollback --repo . --to 3 --reason "retry validation"
```

Rollback restores workflow metadata to the target event's state and appends a
`WORKFLOW_ROLLBACK` event. It must not delete or rewrite prior JSONL events and
must never modify source files, `PLAN.md`, or approval artifacts. The target
must be an earlier valid event index.

## 4. Symbol Graph Test Expansion

Expand local-only graph coverage for:

- JavaScript and TypeScript imports, ownership, and calls;
- Rust `use`, struct ownership, and calls;
- deterministic serialization across repeated builds; and
- unresolved dependencies and ambiguous symbol matches.

The graph remains conservative and must not execute project code or contact an
external service.

## Non-Goals

v0.3.2 does not include:

- OpenAI API calls or API key configuration;
- automatic ChatGPT scraping or browser submission;
- autonomous source-code modification;
- multi-agent planning (reserved for v0.4); or
- destructive rollback of repository files.

## Acceptance Criteria

1. A plan approval cannot become effective without a matching path and SHA-256
   binding.
2. Event queries are filterable, indexed, JSON-capable, and read-only.
3. Workflow rollback is auditable and preserves earlier event records.
4. Symbol graph tests cover the supported language and ambiguity boundaries.
5. The full local quality suite passes without network or API credentials.
